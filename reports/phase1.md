## 2. Test suite

- **35 tests, all passing**, ~0.6 s, no network, no weight bytes.
  Run: `python3 -m pytest -q`.
- Coverage: card parsing + claim extraction; snapshot schema/validation/hashing;
  `local` and `hf` (fixture) adapters; rule-pack loading + version recording;
  **per-class positive** (every planted case fires its class) and **negative**
  (no clean case fires any V1–V7); param-estimate bounds; V8 signal-only +
  heuristic + gate-exclusion + suppression when a base is declared; evidence-pack
  chain verify, tamper detection, snapshot-mismatch detection, report wording
  discipline; bench determinism (same seed → identical bytes), manifest schema &
  strict markers, GATE 1 across multiple seeds; CLI round-trips.

## 3. Implemented (in scope, done)

- **Snapshot layer** — `snapshot/1` schema with validator + canonical content
  hash (D-09). `local` adapter (streams hashes of large files; the only mode that
  touches weight bytes, on the user's own machine). `hf` adapter built against the
  real Hub API shape via an injectable fetcher; tests use recorded-shape fixtures
  (`FixtureFetcher`), a live `HttpFetcher` exists for the optional smoke only.
- **Rule packs (data, versioned independently)** — `hub-metadata-v1`,
  `gpai-eu-v1` (Annex XI/XII + CoP Model Documentation Form; every item cites its
  regulatory source), `license-terms-v1` (compatibility/attribution data model),
  `fingerprints-v1` (V8). Finding sets and evidence packs record pack versions.
- **Verification core** — V1–V7 deterministic, V8 signal-only, as a pure function
  `snapshot JSON → findings JSON`. Each finding carries check, code, severity,
  heuristic flag, and an evidence pointer `{file, field, expected, actual}`.
- **Evidence pack** — `pack/1`, hash-chained over ordered records (D-05);
  `verify-pack` rechecks the chain and (optionally) the snapshot hash fully
  offline; Markdown report generated from the pack with the non-certification
  disclaimer. `docs/bom-mapping.md` gives the CycloneDX ML-BOM / SPDX-AI field
  correspondence (mapping table only, per spec — no converter).
- **Bench Part A** — seeded generator producing the 120-case dev split
  (V1–V7 ×12 = 84, clean 36, incl. near-miss cleans: merge w/ correct paperwork,
  Gemma/OpenRAIL derivatives, a non-commercial license), a manifest with
  `seed`/`cases_sha256`/composition, and a deterministic scorer (per-class recall,
  clean FP; V8 ignored).
- **CLI** — `snapshot`, `verify` (+`--ci`, `--as-of`), `pack` (+`--report`),
  `verify-pack`, `bench generate`, `bench score`.

## 4. Not implemented / limitations (honest)

- **Part B real-release audit — NOT implemented** (Phase 2 scope; untouched, as
  instructed). No real model was audited.
- **Sealed independent holdout — NOT implemented** (Phase 2).
- **HF fixtures are authored to the API schema, not live-captured** (D-11) — this
  environment is offline. They exercise the adapter's parsing of the real shape;
  capturing live bundles from 2–3 small public repos is a Phase-2 smoke task and
  needs no adapter code change.
- **`hf` adapter does not recursively resolve ancestor licenses** (D-12). On an
  `hf` snapshot with a declared `base_model` but unresolved lineage, V3 emits
  `license_unknown` ("判定不能"), never a guessed compatible verdict. The
  synthetic bench supplies `lineage` explicitly, so V3's compatible / incompatible
  / attribution logic is fully exercised there.
- **`fingerprints-v1.known_bases` ships empty** — no real base fingerprints are
  claimed in Phase 1 (honest). V8 is exercised via a test that injects a known
  fingerprint; it will produce no signals on real data until the table is
  populated (Phase 2).
- **Parameter estimate is coarse** (±20% tolerance, D-02) — a gross-mismatch
  cross-check, not a precise parameter count.
- **V6 prose-claim extraction and the minimal YAML parser** handle a deliberately
  bounded subset (SPEC.md §2.1, cardparse docstring). The `hf` path relies on
  the Hub's already-parsed `cardData`, so the minimal YAML parser is used only by
  the `local` adapter on cards we control in tests.
- **BOM converter** not built (mapping table only, as specified).

## 5. Known weak points (to watch)

- Dev-split recall is an in-distribution, mutually-consistent measurement (see the
  §1 caveat). The real risk — that the deterministic rules miss or over-fire on
  *real* cards' messy prose — is unmeasured until Part B.
- V4 documentation detection is keyword/structural; real cards phrase the same
  Annex item many ways, so Part B will need the rule pack's keyword lists widened
  (a data change, not code).
- License compatibility is a versioned data model, not legal truth; it must never
  be read as a compliance verdict (enforced in wording, §1/§9 discipline held
  throughout: no "certificate" wording in any output).
